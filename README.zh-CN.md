# getnote — 把 Get笔记录音拉出来用

一个 Claude skill，对接 Get笔记（Get AI 语音笔记）开放平台：列录音、取 AI 总结、拿带说话人区分的原文转写、下音频文件。

**关键词**：Get笔记 · getbiji · 语音笔记 · 录音转写 · 会议纪要 · ASR 纠错 · 录音分析

## 为什么写这个

Get笔记有开放平台，但没有 SDK，文档里也没写那几个真正会卡住人的地方：

- **翻页不是偏移量。** `?cursor=20` 只会把第一页再给你一次。必须拿上一页响应里的 `next_cursor` 往下传，那是最后一条笔记的 `note_id`。
- **详情接口的参数叫 `id`，不叫 `note_id`。** 值是同一个，参数名不同，写错就报参数错误。
- **列表接口给的是 AI 总结，不是原文。** 带说话人区分的原文只从详情接口来，在 `audio.original` 字段里。
- **原文是语音识别的裸结果**，同音错字、断句混乱一堆，照字面读会读出笑话。

这四件事 skill 里都写了，连带着还写了一套纠错规矩。

## 里面有什么

| 章节 | 内容 |
| --- | --- |
| 接口 | 列表、详情、翻页、音频下载 |
| ASR 纠错 | 同音词纠正、上下文还原、英文缩写交叉验证 |
| 噪音过滤 | 把正事对话和背景里的短视频、游戏音分开 |
| 工作流 | 「分析我最近的录音」→ 列表 → 详情 → 原文 |
| 归档 | 建议的年/月目录结构 |

最有用的不是接口封装，是**纠错纪律**。举个实例：某次识别把 `OPC`（One Person Company）写成 `OBC` 十次。统计各变体的出现次数、再看哪个能在上下文里立住，才判断得出这是误识。skill 把这道检查写死了，不靠运气。

## 安装

把 skill 目录拷进 Claude 的 skills 目录：

```bash
cp -r getnote ~/.claude/skills/
```

然后配两个环境变量：

```bash
export GET_BIJI_API_KEY="你的密钥"
export GET_BIJI_CLIENT_ID="你的客户端ID"
```

也可以写进 Claude Code 的 `settings.json` 的 `env` 块，每次会话自动注入。

## 它不做什么

- 不生产录音，只读你 Get笔记 账号里已有的内容
- 除 Get笔记 自己提供的接口外，不把音频发往任何地方
- 不替你决定留多久、存哪里

## 隐私

录音和转写里是别人说过的话。在把它指向一场会议之前，先确认在场的人接受这件事。文件是写到本地的，最终落在哪由你决定。
